# Credential-Safe Source Refresh Logging

status: planned

## Context

`get_file_by_url()` rejects credential-bearing source URLs before opening a
connection, but `update_all_sources()` currently prints the configured URL
before validation and repeats it when refresh fails. A malformed local source
record can therefore expose embedded credentials in console or CI logs even
though the network boundary rejects the request.

## Priority

This is a narrow secret-exposure defect on the maintained updater path. The
fix should preserve useful source context without reproducing untrusted URL
text.

## Scope

1. Log the source directory rather than the configured URL during refresh and
   failure reporting.
2. Add an offline regression contract proving credential-bearing source URLs
   are neither logged nor fetched through `update_all_sources()`.
3. Keep source validation, redirect policy, response bounds, atomic cached-file
   replacement, generated data, and privileged replacement behavior unchanged.
4. Synchronize the security guidance, README, changelog, and agent guardrail.

## Verification Plan

- Run the focused baseline checker and all four Make gates from the checkout.
- Run the absolute Makefile check from an external directory.
- Compile the Python sources without retaining generated bytecode.
- Reject mutations that restore URL logging or remove the regression call.
- Inspect the exact intended diff, generated artifacts, and changed lines for
  secret patterns before committing.

## Risk And Rollback

The change reduces log detail from a full URL to a source directory. Rollback
restores the prior log messages; no network, generated-hosts, or system-hosts
behavior is otherwise changed.
